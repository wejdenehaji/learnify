Règles communes

Ces règles s'appliquent à tous les sujets de la partie JavaScript.

👥Un binôme

Le projet est réalisé par deux étudiants, comme le prévoit le modèle de rapport (étudiant 1 et étudiant 2). Chacun doit contribuer au code.

🔗Même sujet que la partie HTML/CSS

La partie JavaScript enrichit la page HTML/CSS du même sujet : vous ne repartez pas de zéro. Le sujet 4 n'a pas de fiche JavaScript.

📦Bibliothèques

JavaScript « vanilla » par défaut. Exceptions : Chart.js (ou équivalent) pour le sujet 3 ; pour le PDF du sujet 5, window.print() avec la feuille @media print ou une bibliothèque. Toute bibliothèque est citée dans le rapport.

🗂️Données

Les données sont fictives : un tableau JavaScript ou un fichier JSON local lu avec fetch. L'« actualisation automatique » est simulée avec setInterval. localStorage assure la persistance.

✅Qualité minimale

HTML5 sémantique, responsive (mobile, tablette, desktop), validation W3C, aucune erreur dans la console, labels et focus visible, respect de prefers-reduced-motion.

🐙Dépôt GitHub

Le code est déposé sur GitHub avec des commits réguliers des deux étudiants et un fichier README. Un serveur local (Live Server) est nécessaire pour fetch et les modules.

Fonctionnalités par sujet

Chaque sujet comporte un socle de fonctionnalités obligatoires et des bonus. Les obligatoires sont notées dans le barème ; les bonus ajoutent des points, dans la limite de 20. Le sujet 3 étant plus court, des bonus sont suggérés pour équilibrer la charge de travail.
